## Implementation

### Files Created

#### 1. flow/normalizer.py

**Purpose:** Convert extractor output to canonical schema

**Key Functions:**
- `FlowNormalizer.__init__()` - Load schema, build alias map
- `normalize()` - Complete normalization pipeline
- `_extract_metadata()` - Separate five-tuple and timestamps
- `_apply_aliases()` - Rename columns per schema
- `_apply_conversions()` - Unit conversions
- `_calculate_derived()` - Derived features from base features
- `_select_canonical_features()` - Filter to canonical features only
- `_validate_schema()` - Ensure required features present

**Schema Loading:**
- Reads `config/feature_schema.yaml`
- Extracts required feature list
- Builds alias mapping (extractor → canonical)

**Normalization Steps:**
1. Extract metadata (five-tuple, timestamps, flow IDs)
2. Apply column aliases (CICFlowMeter → canonical names)
3. Apply unit conversions (per schema specifications)
4. Calculate derived features (e.g., bytes per packet)
5. Select canonical features only
6. Validate schema compliance (required features present)

**Error Handling:**
- `ConfigError` if schema file missing/invalid
- `SchemaMismatchError` if required features missing

#### 2. flow/pcap_flow_extractor.py

**Purpose:** Complete PCAP → canonical features pipeline

**Key Classes:**
- `PcapFlowExtractor` - Main pipeline orchestrator

**Pipeline Flow:**
```
PCAP File
    ↓
CICFlowMeterAdapter (extract raw features)
    ↓
FlowNormalizer (normalize to canonical schema)
    ↓
Validation (schema compliance check)
    ↓
(Canonical Features, Metadata, Statistics)
```

**Methods:**
- `extract_flows()` - Complete extraction pipeline
- `get_pipeline_info()` - Pipeline component information

**Outputs:**
- `features` - Canonical feature DataFrame (model input)
- `metadata` - Flow metadata (five-tuple, timestamps)
- `stats` - Extraction statistics and info

**Optional File Outputs:**
- `features.csv` - Canonical features
- `metadata.csv` - Flow metadata
- `raw_features.csv` - Raw CICFlowMeter output (debugging)

**Issue:** If schema changes after training, old models won't work

**Mitigation:** Schema hash recorded in model metadata (registry validates)

**Enforcement:** `SchemaMismatchError` raised if features don't match

## Schema Parity Verification

### Train/Inference Parity Ensured By:

1. **Canonical Schema** (`config/feature_schema.yaml`):
   - Single source of truth for feature names
   - Used by both training and inference
   - Version controlled with code

2. **Normalizer**:
   - Converts any extractor output → canonical schema
   - Validates required features present
   - Raises `SchemaMismatchError` if mismatch

3. **Registry Metadata**:
   - Model stores schema hash at training time
   - Inference validates schema matches
   - Prevents using wrong features

4. **Integration Tests**:
   - Test schema validation logic
   - Verify error raised on mismatch
   - Verify successful normalization

**Parity Document:** `docs/verification/feature_parity.md` (to be created in real testing)

## Feature Extraction Examples

```python
from flow.pcap_flow_extractor import extract_flows_from_pcap
from pathlib import Path

# Extract flows

    output_dir=Path("artifacts/pcap_features")

print(f"Extracted {stats['flow_count']} flows")

print(f"Metadata columns: {stats['metadata_columns']}")

# metadata: DataFrame with src_ip, dst_ip, src_port, dst_port, protocol
# stats: Dictionary with extraction statistics
```
